## 决策与理由

1. **参数方程用 `u` 而不是 `t`。** `t` 已经是播放器进度（动画参数），两者混用会让 `2πt` 与曲线参数互相干扰。代价是用户要习惯 `x=cos(u)`；收益是「动参」与「曲线参数」不再打架。
2. **导出 PNG 放在播放器条而不是侧栏。** 三个模块都能导出，放在共用组件里只实现一次；侧栏属于模块自持，放进去会导致两份实现。
3. **分享只编码函数模块的状态。** 排序/寻路的状态更像「一次操作的回放」，分享出去意义有限；函数图形才是用户想发给别人的东西。
4. **分析标注只对显式曲线生效。** 隐函数/极坐标的零点没有「沿 x 排序」的直觉含义，硬做会给出反直觉的标注。
5. **极值用抛物插值而不是三分搜索。** 采样已给出候选区间，插值一次就能到 1e-3 精度，省掉多轮求值。

## 踩坑

| 坑 | 现象 | 处理 |
|---|---|---|
| 构造参数类型漏字段 | 从 hash 还原时 `entry.a` / `entry.b` 报 TS2339 | 构造器形参补 `a?`/`b?` |
| `hidden` 会连 label 一起隐藏 | 参数方程的第二行与它的 `sr-only` label 用 `hidden` 同步，若 label 一直 `hidden` 就读屏不可达 | 两者同步切换；非参数方程时都隐藏，参数方程时都恢复 |
| 想给 `.curve-exprs` 加 `display:none` 收敛 sr-only | 会把 label 移出无障碍树 | 放弃该样式，sr-only 本身就不占布局 |
| 标注文字在视窗边缘被裁 | `max (7.85, 1)` 贴右边界只显示一半 | 已知外观问题，未修；需要时按 `clamp` 收进画布 |
