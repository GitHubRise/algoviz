## 决策与理由

1. **自己写正交投影，不上 WebGL。** 1600 个四边形用 Canvas 2D 填充 + 排序就够，还能保持「运行时零依赖」；WebGL 会把着色器和上下文管理带进来，和项目其余部分的复杂度不匹配。
2. **正交而不是透视。** 曲面是数据图不是场景，近大远小会让「高度」难以比较；正交也让归一化后的坐标可直接当像素比例用。
3. **x/y 与 z 分开归一化。** 三个轴共用一个比例时，`x²+y²` 在默认视窗（z 到 72）下会被压成一根针——这是渲染出来才发现的，不是判定表能挡住的。z 独立缩放后压到 ±0.7。
4. **ALT+拖动才旋转，普通拖动平移。** 与用户要求一致，也避免和「拖曲线改 a/b」的手势打架；3D 视图下曲线命中检测直接跳过。
5. **3D 视图独占画布。** 2D 网格、坐标轴、其它 2D 曲线在 3D 场景里没有意义；先画复变背景、再画曲面、然后直接返回。
6. **画家算法按面心深度排序。** 正交投影下这个近似足够；真正需要遮挡正确时再上 zbuffer。

## 踩坑

| 坑 | 现象 | 处理 |
|---|---|---|
| 统一归一化把曲面压成针 | `x²+y²` 只剩一根细尖 | x/y 各自归一化、z 独立缩放；补 T-3D09 锁定 |
| 判定表 T-3D04 写反 | 以为 yaw=90° 把 +x 转到屏幕左侧 | 实际转到 +y（屏幕中心、depth=1），改表 |
| 通用提示与 3D 提示重叠 | 画布底部两行字叠在一起 | 3D 分支提前 return，跳过后面的 `surface.hint` |
| 2D 曲线叠在 3D 场景上 | 抛物线画在曲面之上，像浮在空中 | 有曲面时跳过全部 2D 绘制 |

## 遗留待办

- 曲面没有 zbuffer：面片交叉时画家算法会排错。
- 没有光照方向可调，也没有等高线叠加在曲面上。
- 网格固定 40×40，没有自适应；分辨率高的大屏上会看到折面。
- 复变域着色与曲面都没有缓存，拖动时整体重算。
