## 决策与理由

1. **`a`/`b` 既是参数又是平移，用「公式有没有用到」来分野。**
   表达式没写 `a`/`b` 时，渲染层把 a/b 当平移施加（`f(x-a)+b` 的效果）；写了就完全由公式决定，渲染层不再叠加。
   理由：只当平移的话公式里用不了；只当变量的话用户拖一条 `sin(x)` 会毫无反应。这条规则两种直觉都覆盖，且可预测。

2. **拖动命中检测只覆盖显式与极坐标。**
   隐函数要做最近点搜索（对 F 采样），成本高于收益；拖起来也没有「抓住一条线」的直觉。

3. **极坐标固定扫 3 圈。** 玫瑰线一圈就闭合，螺旋需要多圈；3 圈是折中，多画的重复线段在视觉上不可辨。

4. **粘贴规范化在 NFKC 之前处理上标。**
   NFKC 会把 `²` 直接折成 `2`，之后再想还原上标就没依据了。这是实测踩到的坑，已写进 `docs/300002`。

5. **粘贴走两条路**：输入框上的 `paste` 事件（用户主动粘贴）与文档级 `paste`（焦点不在输入框时），再加一个读剪贴板的按钮兜底（浏览器可能拒绝）。

## 踩坑

| 坑 | 现象 | 处理 |
|---|---|---|
| NFKC 吃掉上标 | `x²` → `x2`，T-N03 红 | 上标替换移到 NFKC 之前 |
| 合成 pointerdown 抛错 | 无真实 pointerId 时 `setPointerCapture` 抛 `InvalidPointerId` | 两处 `setPointerCapture` 包 try/catch（也提升真实环境健壮性） |
| 新增模式下拉触发 a11y issue | 「should have id or name」计数 +2 | 给 mode select 补 id 与 `sr-only` label |
| 截图偶发超时 | DevTools 截图在持续 rAF 的页面上间或 timeout | 重试或改用 JPEG/视口截图，不影响功能 |

## 遗留待办

- 隐函数每帧约 2 万次求值，拖拽/缩放时可能有帧率压力，未做基准。
- 参数方程（x(t), y(t)）仍未支持，需要两个表达式槽。
- 极坐标圈数、隐函数分辨率都还是硬编码常量。
