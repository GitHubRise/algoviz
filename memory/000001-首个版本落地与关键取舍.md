## 决策与理由

1. **时间抽象用归一化进度，而不是帧索引或绝对时间。**
   函数是连续量（`t` 扫过 0..1），算法是离散量（第 k 帧）。只有 0..1 能同时承载，且进度条拖拽天然对应。
   可推翻条件：出现「不同段速度不同」或「一帧不等权」。

2. **不引入 UI 框架。** 三个模块的表单量很小，原生 DOM 构造器（`core/dom.ts`）约 40 行就够；产物因此只有 46 KB。
   可推翻条件：模块数 > 6，或表单出现复杂的跨字段校验。

3. **表达式不用 `eval`。** 改为 AST → 闭包树，代价是要自己写 Pratt 解析器（约 140 行），收益是可在严格 CSP 下运行、错误能定位到字符下标。

4. **排序把每一步录成整帧快照（复制数组），不做增量。** n=72 最坏 3.4 MB，换来「任意拖拽/回退都正确」的实现简单性。
   可推翻条件：n 上限提到 150（约 15 MB）。

5. **寻路分两阶段揭示：先扩散、后路径。** 若把最终路径一开始就画出来，就失去了「搜索过程」的观察价值。

## 踩坑

| 坑 | 现象 | 处理 |
|---|---|---|
| `ParseError` 未再导出 | `evaluate.ts` 从 `parser.ts` 导入得到 `undefined` → `is not a constructor`，T-E13 红 | 在 `parser.ts` 加 `export { ParseError } from './lexer'` |
| `theme.danger` 不存在 | tsc 报属性不存在 | 主题补 `danger: '#ff6b6b'` |
| 一元负号与幂的结合性 | 若不特判会算成 `(-2)^2=4` | 一元负号按 minBp=25 解析，幂 40，得 `-(2^2)` |
| `textBaseline` 写成 `'alpha'` | tsc 报类型错（应为 `'alphabetic'`） | 改正 |
| pivot 高亮被比较色覆盖 | 比较到基准时基准变黄 | Recorder 记录 `pivotIndex`，比较时对该位置用紫色，交换时跟着移动 |
| 判定表把 `heap` 写进用例 | 未知算法会抛错，用例必红 | 改为 `insertion`（heap 未实现，不放进表） |
| 表单 label 未关联控件 | DevTools 报 9 条 a11y 提示 | `field()`/`slider()` 生成 id 并设 `htmlFor`；提示降到 2 条（transport 控件，已补 `aria-label`） |
| 首屏 404 | `favicon.ico` 缺失 | 改为内联 SVG data URI |
