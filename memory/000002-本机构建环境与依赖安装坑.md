## 事实与数字

| 项 | 值 |
|---|---|
| npm registry（全局配置） | `http://127.0.0.1:8081/repository/npm-group/`（本机 Nexus） |
| Nexus 状态 | 未启动 → 安装卡在连接，无输出、不退出 |
| 可用镜像 | `https://registry.npmmirror.com`（淘宝） |
| pnpm | 随 DSH 运行时分发，版本 10.x |
| node | v22.17.1 |
| 实装版本 | vite 6.4.6、typescript 5.6.3、vitest 2.1.9、tsx 4.23.15 |

## 决策与理由

1. **只在单次命令上加 `--registry`，不改全局配置。** 与 `NETWORK.md` 的约定一致：不污染机器与仓库配置；Nexus 恢复后不需要回滚任何东西。
2. **pnpm 的构建脚本白名单写进 `pnpm-workspace.yaml`，不写进 `package.json`。** pnpm 10 起 `package.json` 的 `"pnpm"` 字段被忽略（有明确告警），设置只能放前者。
3. **`verifyDepsBeforeRun: false` 保留在仓库里。** 它不为某个具体机器服务，而是避免「脚本明明成功却 exit 1」误导 CI。

## 踩坑

| 坑 | 报错原文（节选） | 处理 |
|---|---|---|
| Nexus 未启动 | 无输出，进程挂起 | kill 后改镜像 |
| esbuild 安装脚本被拦 | `[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: esbuild@0.21.5, esbuild@0.25.12` | `pnpm-workspace.yaml` 加 `onlyBuiltDependencies: [esbuild]` |
| 设置位置错 | `The "pnpm" field in package.json is no longer read by pnpm` | 迁移到 `pnpm-workspace.yaml` |
| 脚本前校验误判失败 | `[WARN] The install that runs before scripts failed…` 导致 `pnpm test` exit 1（用例其实全绿） | `verifyDepsBeforeRun: false`；或直接 `pnpm vitest run` 绕过 |
| 没有 `vite-node` 可执行文件 | `'vite-node' is not recognized` | spike 改用 `tsx`（新增 devDependency） |
| `pnpm rebuild esbuild --registry=…` | `Unknown option: 'registry'` | rebuild 不接受 registry，先 install 再 rebuild |

经验：`pnpm test` 的退出码要连「执行前的依赖校验」一起看；判断用例是否真的过了，优先看 vitest 自己的汇总行。

## 遗留待办

- Nexus 恢复后可继续用它安装；届时无需改仓库文件。
- 若要把 CI 迁到 GitHub Actions，`verifyDepsBeforeRun: false` 也应保留（Actions 里 `pnpm install` 前置步骤会自己做好校验）。
