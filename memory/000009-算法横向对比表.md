## 决策与理由

1. **对比做成「一次算完的纯函数」，不是并行播放。** 并行播放要改渲染架构（多画布/多时间轴）；而「比较次数、访问节点数」本来就是标量，表格比动画更能说明问题，成本也低一个量级。
2. **表格随数据自动刷新，不做防抖。** n=72 时 8 种算法约 80ms，拖动规模滑杆会顿一下但能接受；加防抖会让「拖到某档后表还是旧值」更困惑。已记进当前状态，后续要优化再加。
3. **计数排序在表里比较列恒为 0。** 这是它的本质（非比较排序），表格直接呈现比额外注释更有说服力；判定表 T-CMP02 锁住这条。
4. **当前算法高亮。** 表格和上面的柱子是同一组数据，高亮让「表里这一行就是画布上在跑的那个」不言自明。

## 踩坑

## 实测读数（39×23 迷宫，A* 为当前算法）

| 算法 | 可达 | 代价 | 访问 |
|---|---|---|---|
| BFS | 是 | 56 | 893 |
| DFS | 是 | 60 | 63 |
| Dijkstra | 是 | 56 | 894 |
| A* | 是 | 56 | 328 |
| 贪心 | 是 | 56 | 57 |

这组数字正好说明三件事：DFS 不保证最短（60 > 56）；A* 用 328 次访问换到与 BFS 相同的最短路径；贪心访问最少但换个地图就可能绕路。

## 遗留待办

- 对比表调用是同步的，数据规模再大就要挪到空闲时段或 Web Worker。
- 排序表只比较次数/写入/帧数，没有时间维度（时间在高精度计时下噪声太大）。
